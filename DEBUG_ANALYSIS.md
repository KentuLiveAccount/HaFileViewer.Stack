# Debug Viewport Analysis - Empty Lines Issue

## Executive Summary

The debug script has successfully identified the source of the empty line bug. When scrolling down to line 30, the viewport contains **2 empty lines at positions 27 and 29**, appearing in an **alternating pattern** within the viewport.

## Key Findings

### 1. Empty Lines Pattern at Line 30

When viewport shows lines 6-30:
- **Line 27**: `len=0  <EMPTY>`
- **Line 29**: `len=0  <EMPTY>`

These are **2 consecutive logical empty lines** that appear at odd positions in the viewport.

```
  Total lines in viewport: 25
  Empty lines: 2
```

### 4. Persistent Empty Lines Issue

After reaching line 30, **every subsequent scroll contains empty lines** until scrolling back up to around line 52. The pattern shows:
- Lines 3-31: Empty lines detected
- Lines 4-32: Empty lines detected
- ... continuing ...
- Lines 76-100: Empty lines detected (reached end)

### 5. Scroll-Back Behavior (Critical Bug)

When scrolling back up from line 100:
- Scrolls successfully down to around line 52
- **Then suddenly stops at line 15** (should go to line 1)
- **Only scrolled up 61 times** instead of the expected ~75-76 times to reach line 1

This indicates:
1. Empty lines are being counted in scroll operations
2. The scroll-back stops prematurely when encountering empty lines during reverse traversal
3. There's a logic error in how empty lines affect the `scrollUp` operation

## Root Cause Analysis - CRITICAL FINDING

**The empty lines are NOT in the actual file!**

Verification shows:
- Total lines in file: 71,356
- **No empty lines found** in the file itself
- Lines 20-35 all contain valid log entries

This means:
1. **Empty lines are being GENERATED by the LineCache or viewport logic**
2. The cache is returning empty Text values for certain line numbers
3. This is a **caching/line-reading bug**, not a file issue
4. The empty lines appear at specific positions: 27, 29, etc. during scrolling

**Likely causes:**
- Line position calculation mismatch between cache and file
- Offset tracking error in the bidirectional scanner
- Cache returning wrong content for certain line numbers
- Incorrect line boundary detection during scrolling
