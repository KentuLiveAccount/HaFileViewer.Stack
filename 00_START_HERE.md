## Project: HaFileViewer - Viewport Empty Lines Investigation

## What Was Done

A comprehensive debug investigation was conducted to identify and document a critical bug in the viewport rendering system where **empty lines appear at alternating positions during scrolling**.

## Key Results

### ✓ Bug Identified
- Empty lines appear at lines 27, 29, 31, 33... (alternating)
- Pattern is 100% reproducible and consistent
- **Empty lines are NOT in the actual file** - they are generated by viewport logic

### ✓ Root Cause Located
- Bug is in the `scrollDown` operation in `Operations.hs`
- Likely cause: incorrect `cursorBottomPosition` parameter when calling `getLinesFrom`
- Systematic offset error (~half a line) in byte position tracking

### ✓ Evidence Documented
- Direct cache reads are correct (no empty lines)
- Incremental scroll reads return corrupted data
- File verified: 71,356 lines, 0 empty (no empty lines in actual file)

### ✓ Impact Analyzed
- Scroll-down shows empty lines after 5-6 operations
- Scroll-up stops at line 15 instead of line 1 (fails to reach beginning)
- Core functionality is broken

## Critical Findings Summary

### The Bug Pattern

```
Correct data        Corrupted by scrollDown
(from direct read)  (from incremental scroll)
─────────────────   ────────────────────────
Line 26: 243 ch  →  Line 26: 23 ch   (TRUNCATED)
Line 27: 223 ch  →  Line 27: 0 ch    (EMPTY)
Line 28: 242 ch  →  Line 28: 243 ch  (OK)
Line 29: 224 ch  →  Line 29: 0 ch    (EMPTY)
Line 30: 243 ch  →  Line 30: 223 ch  (SHIFTED)
```

### Root Cause Location

**Primary Suspect: Operations.hs - scrollDown()**

```haskell
(moreLines, topPos, bottomPos) <- getLinesFrom cache 
                                   (cursorBottomPosition cursor)  ← WRONG?
                                   Forward 
                                   1 
                                   startLineNum
```

The `cursorBottomPosition` is likely incorrect or not properly updated.

### Evidence Chain

1. ✓ File has 71,356 lines with 0 empty lines
2. ✓ Direct cache reads (getLinesFromStart) are correct
3. ✗ Incremental scroll reads (scrollDown) are corrupted
4. ✗ Bug is deterministic and repeatable
5. ✗ Pattern suggests off-by-half-line byte offset error
