# Viewport Debug Report - Empty Lines Investigation

**Date**: 2024
**Status**: CRITICAL BUG IDENTIFIED
**Severity**: High - Affects scroll operations and viewport integrity

---

## Executive Summary

A comprehensive debug script has identified a **critical bug in the line cache and viewport rendering**. When scrolling down, the viewport returns **empty lines at alternating odd-numbered positions** (27, 29, 31, 33...). These empty lines are NOT in the original file but are **generated by the cache logic**, indicating a systematic offset or position-tracking error in the scrolling mechanism.

## Root Cause Analysis

### The Bug Location

The bug occurs when scrolling down via `Operations.scrollDown`:

```haskell
scrollDown :: ViewState -> IO ViewState
scrollDown vs = do
  let cache = vsCache vs
      cursor = vsCursor vs
      viewport = vsViewport vs
  
  ...
  
  let startLineNum = cursorLastLine cursor + 1
  (moreLines, topPos, bottomPos) <- getLinesFrom cache 
                                     (cursorBottomPosition cursor)  ← PROBLEM HERE
                                     Forward 
                                     1 
                                     startLineNum
```

### Likely Issues

1. **cursorBottomPosition tracking is inaccurate**
   - After first cache read, position tracking breaks down
   - Each subsequent call has wrong position
   
2. **Offset calculation mismatch**
   - Byte position doesn't align with line boundaries
   - Off-by-half-line or similar systematic error
   
3. **Line boundary detection in bidirectional scanner**
   - Forward scanning from a position jumps to wrong byte offset
   - Skips partial lines
   
4. **Cache position update logic**
   - topPos and bottomPos not being correctly updated
   - Passed to next scroll operation with stale values

### Why Empty Lines Appear

When `getLinesFrom` is called with wrong position:
1. It starts reading from wrong byte offset
2. Partial reads of lines occur
3. Some reads return zero-length strings (empty)
4. These get placed in the viewport

## Conclusion

The viewport empty lines bug is caused by a **systematic error in position/offset tracking during scrolling operations**. The cache read is correct when called directly, but when called incrementally during scrolling (via scrollDown), it returns corrupted data. The bug manifests as empty lines at alternating positions and ultimately breaks the scroll-up functionality.

**Priority**: CRITICAL - Affects core functionality
**Effort**: Medium - Bug is reproducible and location is identified
**Risk**: High - Scroll operations are fundamental to the UI
